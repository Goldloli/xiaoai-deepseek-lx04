# LX04 启动调试试装方案

> 历史方案：本文为首次试装前的准备记录，“尚未验证”等描述只对应当时。最终 V6 及验收结论见[改造过程与修改技术报告](改造过程与修改技术报告.md)，不要将这里的初始候选直接当成最终交付版本。

目标是在原厂中国版系统中开放经过密钥认证的 USB ADB，后续把 DeepSeek 接入程序安装到音箱。Mac 只负责安装维护。大模型推理仍需调用 DeepSeek 云端 API；这里准备的镜像不包含本地 DeepSeek 模型。

## 已完成的准备

- 原厂 eMMC USER、BOOT1、BOOT2 已备份；关键分区和完整镜像中的对应内容一致，GPT 校验通过。
- 实机重新读取确认：MT8167、原厂 boot_a / boot_b 与备份一致，当前优先启动 B 槽，两个槽都标记为成功启动。
- 原厂启动锁处于锁定状态。芯片硬件加密校验识别为 V3；解锁候选经解密验证，再转回锁定状态，能逐字节还原原始校验数据。
- B 槽调试候选来自本机原厂 boot_b；加入 Magisk 初始化与 USB ADB 设置，保留 ADB 密钥认证。镜像制作时保留原厂加密、verity 设置；仅通过静态校验，尚未验证实际启动。
- `scripts/lx04_boot_trial.py --check-device` 已在实机完成，只读取、不写入。

## 拟执行的写入

1. 再次验证原件与槽位；任何不符都停止。
2. 写入 boot_b 的 16 MiB 调试镜像并读回比较。
3. 写入 seccfg 的第一个 512 字节扇区：锁状态由 1 变为 3，重算对应加密校验；verity 状态及其他字节保持原值。再读取整个 seccfg 比较。
4. 请求正常启动，等待经过密钥认证的 USB ADB；核实原厂桌面、米家和天气功能后才继续安装客户端。

脚本不写 boot_a、system、vendor、userdata、RPMB，不运行格式化或 fastboot 标准解锁命令，不切换启动槽位。

## 实际风险和回退

这一步会改变启动锁状态并加载修改过的启动代码。候选尚未在这台机器上启动，可能无法开机；保留镜像中的加密设置，也不能保证启动锁变化不会影响加密数据访问或原有绑定。原厂备份不是保证一切都能恢复的承诺。

写入或读回失败时，脚本尝试立即回写原厂 boot_b 和 seccfg 并验证。如果设备已掉线，需要重新进入下载模式，再运行 `scripts/lx04_boot_trial.py --restore`。遇到恢复菜单时不选择清除数据、恢复出厂或格式化。

实际试装命令是 `scripts/lx04_boot_trial.py --apply`，不带参数只检查本地文件。本方案准备完成时，尚未执行实际写入。

## 启动槽位判定参考

实机 para 的 0x800 处为 MediaTek bootctrl 1.0 元数据（magic 0x19191100）。A/B 优先级分别为 6 / 7；判定对应 [bootctrl.h](https://github.com/svoboda18/lk/blob/37ec8bcbc4361c0e267617f517d154656804c17a/platform/common/bootctrl/1.0/bootctrl.h) 和 [get_suffix](https://github.com/svoboda18/lk/blob/37ec8bcbc4361c0e267617f517d154656804c17a/platform/common/bootctrl/1.0/bootctrl_api.c)。该公开代码用于解释格式，实机启动槽位仍需在开放调试后用运行时属性复核。
