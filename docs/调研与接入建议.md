# 小爱触屏音箱 LX04 接入 DeepSeek：调研与实机初检

> 历史文档：以下内容保留初检和方案探索时的状态；最终方案已完成音箱本机运行、无前缀分流及联网搜索。请先阅读[改造过程与修改技术报告](改造过程与修改技术报告.md)和[使用与维护](使用与维护.md)。

> **当前目标已调整（2026-10-24）**：接入程序与配置保存在 LX04 本机，日常使用不依赖 Mac/NAS 常开。下文 Mac 部署方案仅保留作前期调研参考，不作为当前实施方案。
>
> **可行性判断**：音箱本机运行轻量客户端并调用云端 DeepSeek，有技术可行性，但尚未验证本机安装入口、原生语音链路接入及后台常驻。完全离线、在音箱内运行具有实用问答能力的 DeepSeek，不作为可行目标。
>
> **新增证据**：LX04 原始 TWRP 设备树列出 MT8167 / Cortex-A35、1GB RAM、4GB 存储、Android 8.1：https://github.com/MaxCaiLC/twrp_xiaomi_lx04_device_tree/blob/android-8.1/README.md 。这些是社区记录，尚未从本机独立读取。
>
> LX04 已有第三方 APK 实测项目：https://github.com/linyoujie/xiaomi-codex-bridge 。它证明已开启 ADB 的 LX04 可安装定制 APK，不代表已经实现语音接入或提供当前固件的解锁方法。
>
> AyraHikari/xiaomi-x04g-lx04 提供分区备份及中外版转换资料，但其中 root-adb-debug.md 明确针对 X04G，不可直接把其中的全球版 boot 镜像用于当前 LX04。TWRP/解锁案例也不能等同于已找到适合固件 2.42.118 的现成补丁。
>
> **优先验证路线**：保留中国版原系统 → 确认安装/调试入口 → 在可读取分区后先备份 → 安装兼容 Android 8.1 的本机轻量服务 → 尝试读取小米云端对话记录并调用 DeepSeek，再调用原生播报。此路线可减少对麦克风的争用，但其 Android 移植、账号验证、停止播放与常驻机制仍需验证。原生语音进程 Hook 作为更深度的后续研究，不先承诺。
>
> 当前仍处于研究与只读检查阶段，未刷写、解锁、重分区或安装音箱端程序。


调研日期：2026-10-24。当前只完成资料核实与设备识别，尚未登录小米账号、调用付费模型接口或完成音箱端到端验证。

## 实机结果

- Mac USB 注册表识别到 XiaoMi LX04，序列号尾号 47316，与用户截图吻合。
- USB VID:PID 为 18d1:2d00，当前接口名称 Android Accessory Interface。
- 已从 Google 官方下载 Platform-Tools 到本项目 tools/，用于检查。
- adb devices -l 和 fastboot devices 均未列出设备。当前不能通过这两个接口读取系统属性、文件或安装软件；此结果不代表设备永久不能开启调试。
- 固件 2.42.118 来自用户截图，尚未通过设备接口独立验证。
- 初始 ARP 缓存没有匹配截图中的音箱 MAC；这不足以判断音箱是否在同一局域网，尚未确认音箱 IP。
- 本机默认 Python 3.15.0；xiaogpt 当前文档要求 Python 3.12–3.14，部署时应使用独立 Python 3.12 环境。本机已有 uv。

## 已核实的开源方案

1. xiaogpt：https://github.com/yihong0618/xiaogpt
   当前未归档。源码包含 LX04；README 指出该机型可能需要 use_command，使用原生 TTS。ChatGPTBot 接受自定义 api_base 和模型名，可连接 DeepSeek 的兼容 API。适合首先验证。
   2026 年 LX04 用户实测讨论：https://github.com/yihong0618/xiaogpt/issues/614
   该讨论报告基础交互恢复正常，但自动再次唤醒和连续对话存在限制。
2. MiGPT：https://github.com/idootop/mi-gpt
   当前已归档、停止维护。适配表明确列出 LX04 为正常运行但不支持连续对话，streamResponse 应设为 false。
   https://github.com/idootop/mi-gpt/blob/main/docs/compatibility.md
   适配表引用的 LX04 用户反馈：https://github.com/idootop/mi-gpt/issues/92#issuecomment-2184678990
3. xiaobot：https://github.com/axcom/xiaobot
   Go 实现，带网页配置，配置表包含 LX04。作者主要实测 L05C，因此不能把配置表视作本机已验证。其网络监控模式会影响原有音乐等功能，不符合本次优先保留原功能的目标。
4. Open-XiaoAI：https://github.com/idootop/open-xiaoai
   项目说明仅适用于 LX06 和 OH2P，不适用于当前 LX04，不应使用这些型号的固件或刷机步骤。

DeepSeek 官方接口：https://api-docs.deepseek.com/
当前首页列出 https://api.deepseek.com 和 deepseek-flash / deepseek-v4-pro。本示例选择 deepseek-flash，实际可用模型还需在用户账号下验证。

## 建议架构

语音 → 原生小爱/小米云端识别 → Mac 上 xiaogpt 读取对话记录 → 仅处理以“请问”开头的问题 → DeepSeek API → 原生 TTS 在音箱播报。

- “小爱同学，打开卧室灯”“小爱同学，今天天气怎么样”：不带触发前缀，由原生小爱处理。
- “小爱同学，请问为什么天空是蓝色的”：转给 DeepSeek。
- 程序在 Mac、NAS 或服务器上运行，并非把大模型装入音箱。
- Mac 上的程序停止时，新增 AI 链路停止；原生功能仍由原系统提供，最终需实测回归。
- 依赖小米登录、对话记录接口和网络，也可能受到账号验证或接口变更影响。
- 可能出现小爱先短暂抢答、等待后才播放 AI 回答；先做一问一答，暂不启用持续对话。
- 多轮上下文记忆与免唤醒连续对话不同：能保留聊天上下文，不代表能自动持续收音。
- 本方案不承诺将 AI 回答显示到屏幕，先验证语音播报。

## 部署步骤（待用户在本机配置凭据后进行）

以下是后续操作说明，本次尚未执行安装 xiaogpt 或登录。

```sh
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python 'xiaogpt[locked]'
cp xiao_config.example.json xiao_config.json
```

在本机终端设置 MI_USER、MI_PASS、OPENAI_API_KEY；最后一个变量应填 DeepSeek API Key。不要把密码或 Key 发到聊天里，也不要把它们写进提交到 Git 的文件。示例配置没有保存这些凭据，xiaogpt 会读取环境变量。

先运行 `.venv/bin/miservice list` 获取绑定设备列表，必要时按提示完成小米短信/邮件验证；结合型号、设备名确认目标设备，再设置 MI_DID。DID 是小米云端设备标识，不是 USB 序列号。登录工具可能保存认证 token，应留在本机。

启动：

```sh
.venv/bin/xiaogpt --config xiao_config.json
```

示例配置使用 use_command=true、tts=mi、stream=false，只处理“请问”开头的问题。mute_xiaoai=true 在源码中配合触发判断，仅对需要交给 AI 的问题尝试停止原生回答；仍需实测本机停止播放接口表现。不要把触发词改成常见设备控制语句，也暂时不要说“开始持续对话”，以免后续所有问题都进入 AI 路径。

## 验收顺序

1. 用小米登录工具确认云端设备身份；测试音箱能否播报一段短文字。
2. 单独测试 DeepSeek 请求成功，再连接完整语音流程。
3. 说“请问为什么天空是蓝色的”，检查 AI 回答与等待时长。
4. 分别验证天气、米家开关、音乐、闹钟没有被 AI 触发词拦截。
5. 停止 Mac 程序，确认音箱原生功能正常。
6. 最后才考虑自启动或迁移 NAS，避免在首次验证前增加复杂度。
