## 原厂锁定设备：公开了什么

全部实现脚本和关键迭代都保留，具体数值只描述原机，不能直接换到自己的设备执行：

1. **主机 USB 与读取**：固定 mtkclient 提交 `7cb40e727727dfe3faa065eefb29b16ed29bbdf1`，应用 [macOS 补丁](mtkclient-macos.patch)。Apple Silicon 路径假定 Homebrew libusb 位于 `/opt/homebrew/lib`；其他环境自行调整。按音量＋上电进入 BROM，初始 USB `0e8d:0003`，DA 可能重枚举为 `0e8d:2001`。原机用 `--noreconnect` 避免自动重连误选；高速重枚举后重新比较 GPT。
2. **先备份并验证**：读取 GPT、eMMC USER/BOOT1/BOOT2 与关键分区。原机 USER 是 `0xec000000` 字节，27 个 GPT 分区；备份长度、SHA-256、GPT CRC 和独立分区副本都验证后才写入。RPMB 不在原机备份内。实际命令与参数以这个固定提交的 mtkclient README/帮助为准，不能把其他版本教程的地址当作本机布局。
3. **离线制作启动候选**：`scripts/prepare_adb_boot.py` 使用自己的关键备份清单、同版 Magisk 30.7、主机可运行的 magiskboot、自己的 ADB 公钥。从本机 system 区读取原厂 `/adb_keys`，保留它们，加入本机公钥。legacy SAR 内核仅将唯一的 `skip_initramfs\0` 等长改为 `want_initramfs\0`。保留加密与 verity。
4. **锁候选计算**：`scripts/prepare_seccfg.py` 读取 live DA，并用芯片密码外设验证原始 seccfg，计算状态 1→3 的候选，再反算回锁定头部并比较。它不写 flash，但导入即执行设备读取，不能当普通模块导入或拿来做“语法检查”。
5. **有边界试装**：`scripts/lx04_boot_trial.py` 默认只校验本地文件；`--check-device` 才读取设备，`--apply` 才写入。地址白名单限定 boot_b 的 16 MiB 和 seccfg 首 512 字节，并有原件散列、GPT、槽位与读回检查。它内置原机散列，其他设备即使同型号也可能因 seccfg 不同而被拒绝。不要为通过检查删除这些约束。
6. **V2–V6 迭代**：`scripts/revise_adb_boot.py --revision N` 仅制作该版本候选，增加 `--apply` 才写入。V6 由 Magisk-domain oneshot 将 RAM 中的合并公钥 bind mount 到 `/adb_keys`，不关闭认证；USB `0x0601` 表示服务确认挂载并找到本机公钥。V4 只写入但未启动验证，历史记录没有把它列为成功版本。
7. **数据目录运行环境**：开放 ADB 后检查 Magisk 运行组件。原机从同一官方 APK 的 `lib/armeabi-v7a/` 提取 busybox、magisk、magiskboot、magiskinit、magiskpolicy，对应文件名去掉 `lib` 前缀和 `.so` 后缀；配套 `assets/` 中的 util_functions.sh、boot_patch.sh、addon.d.sh、stub.apk 一同补齐到 `/data/adb/magisk`。精确来源与历史散列见[验证摘要](验证与构建摘要.json)。这一步不刷启动分区，须先保留已有运行环境，不能覆盖别人的不同版本组件。

完整解释、实际失败与阶段证据见[技术报告](改造过程与修改技术报告.md)、[操作记录](实机操作记录.md)。仓库不分发 Magisk、主机二进制或原厂分区内容；应从官方源码/发布版本取得工具。历史主机 magiskboot 可执行文件未作为可复现构建工具分发，需自行取得适用于主机架构的实现并验证行为；不能只凭文件名认定来源相同。

历史脚本还依赖未发布的本机文件：`backups/critical-manifest.json`、分区备份、`artifacts/` 中按前序步骤生成的候选清单、`tools/magisk-host/` 和 Python 环境中的 dissect.extfs、dissect.util、mtkclient 依赖。它们是流程前置条件，克隆仓库不会自动产生。代码中的分区地址、散列和布局是复现原机工作的证据；迁移到新设备需要独立识别、备份与代码审阅，不是更换一个序列号即可刷入。

## 恢复与停止

有正常 root ADB 时，优先通过 [维护指南](使用与维护.md) 的 `disabled` 标记停用附加程序并重启。播放无声可调用 `lx04-agent -restore-audio`，它尝试恢复先前保存的主播放静音状态。

启动失败但能重新进入 DA 时，历史 `scripts/lx04_boot_trial.py --restore` 尝试从核验后的**原机**备份回写 boot_b 和 seccfg 首扇区并读回。它不会自动格式化、切槽或回写整盘。不要在已解锁的自定义启动镜像仍被使用时自行单独重新上锁。

raw 回写不能撤销所有 Android 文件、配置、令牌和持久 USB 设置；锁状态变化也可能影响加密数据。原机没有在最终稳定状态执行整机回退演练，因此没有“保证不丢数据”或“保证救砖”的结论。不要选择恢复出厂/清除数据来替代已审阅的恢复路径。

## 常见问题

| 现象 | 已知原因/下一步 |
| --- | --- |
| 正常桌面但没有 ADB | 原厂可能只有 Accessory USB，不等于硬件故障 |
| unauthorized 且没有授权弹窗 | 原机 adbd 只读 `/adb_keys`，MiSystemUI 没有常见授权 Activity；检查公钥挂载，不要反复等待弹窗 |
| macOS `e00002c5` 或连接反复被抢占 | 检查 O+Connect 的 KeepAlive root 服务；独立 ADB 端口不独占 USB |
| DNS 超时 | 检查音箱私密 `dns-server.txt` 的 IP:端口、路由及 CA 环境 |
| 重启没有 agent | 查看新的 boot_id、Magisk 日志和 ready 时间；旧 PID 不能证明已自启 |
| “明天穿什么”走错模型 | 提交脱敏后的原句，补充规则及反例；无需刷启动镜像 |
| 搜索失败或仍说无法核实 | 检查服务商接口/余额/模型、超时及脱敏状态，不把旧知识伪装成搜索结果 |

O+Connect 排障时，本次用户使用 `sudo launchctl bootout system/com.oplus.dsp.core` 停止当前系统会话的服务，没有删除 plist 或持久禁用。只在确认机器确实安装该服务时执行；它会停止 O+Connect 后台功能。历史临时暂停脚本为 `scripts/release-oplus-usb.sh`，到期恢复；这与彻底停止是两种不同选择。
