# 部署指南：已有认证 root ADB 的 LX04

本指南面向已经开放 **USB 密钥认证 root ADB** 的中国版 LX04 / Android 8.1。原厂锁定设备先读[兼容性与恢复](兼容性与恢复.md)。本文命令供其他使用者审阅后执行；开源整理没有对原机重新部署。

## 1. 构建与确认设备

在仓库根目录运行 `make test && make build`。安装 [Google Platform-Tools](https://developer.android.com/tools/releases/platform-tools)，将 `adb` 加入 PATH；有多个设备时用 `-s` 明确选择，不能凭第一台设备操作。

```sh
adb -P 5038 devices -l
adb -P 5038 shell id
adb -P 5038 shell getprop ro.product.model
adb -P 5038 shell getprop ro.build.version.sdk
adb -P 5038 shell getprop ro.adb.secure
```

本文假定 shell 的 `id` 已是 root、SDK 为 27、ADB 认证为 1。若只有普通 shell，需要先自行确认可用的 root 方式并改写命令；不要对其他系统照搬音频 Binder 编号。O+Connect 可能占用 USB，关闭 GUI 不一定停止后台服务，见[排障](兼容性与恢复.md)。

## 2. 准备私密配置

```sh
mkdir -p .secrets
chmod 700 .secrets
cp speaker-config.example.json .secrets/speaker-config.json
cp device-match.example.json .secrets/device-match.json
chmod 600 .secrets/*.json
```

在本地编辑器中填写：

| 文件/字段 | 值 |
| --- | --- |
| `speaker-config.json`: `account`、`password` | 绑定音箱的小米账号和密码 |
| `openai_key` | DeepSeek 开放平台 Key，不能用 App 密码代替 |
| `bot` | 账户实际可用的模型 ID；示例为原机验证的 `deepseek-flash` |
| `mi_did` | 初次可留空，由初始化程序精确匹配后保存 |
| `device-match.json`: `serial_number` 或 `mac` | 从自己的小米设备页面读取，至少填一项；两项都填时必须同时匹配 |

默认模型后端是 `https://api.deepseek.com`。`openai_key` 只是兼容字段名，不代表需要 OpenAI 账号。模型可用性可由 `lx04-netcheck` 查询，费用及搜索接口以提供商当时文档为准。

另在 `.secrets/dns-server.txt` 写一行本网络可用的 DNS **IP:端口**，例如你自己的路由器 IP 加 `:53`；不要填写域名，不要机械复制其他家庭的 IP。配置不要放进 Issue 或命令行参数。

## 3. 传入程序与配置

```sh
adb -P 5038 shell 'umask 077; mkdir -p /data/adb/lx04-deepseek; chmod 700 /data/adb/lx04-deepseek'
adb -P 5038 push dist/lx04-agent dist/lx04-bootstrap dist/lx04-netcheck dist/lx04-searchcheck /data/adb/lx04-deepseek/
adb -P 5038 push .secrets/speaker-config.json /data/adb/lx04-deepseek/config.json
adb -P 5038 push .secrets/device-match.json /data/adb/lx04-deepseek/device-match.json
adb -P 5038 push .secrets/dns-server.txt /data/adb/lx04-deepseek/dns-server.txt
adb -P 5038 push scripts/device-run.sh /data/adb/lx04-deepseek/run.sh
adb -P 5038 shell 'cd /data/adb/lx04-deepseek; chmod 700 lx04-* run.sh; chmod 600 config.json device-match.json dns-server.txt'
```

不要覆盖已有使用者的私密配置和令牌。更新原有安装时先停用程序，备份当前程序及文件，保留配置，仅替换已审阅的新程序；首次部署和更新不是同一操作。

## 4. 初始化小米会话

在一个终端打开设备 shell，设置本进程 HOME、CA 和 DNS，然后登录：

```sh
adb -P 5038 shell
cd /data/adb/lx04-deepseek
export HOME=/data/adb/lx04-deepseek
export SSL_CERT_DIR=/system/etc/security/cacerts
export XIAOBOT_DNS_SERVER="$(cat dns-server.txt)"
./lx04-bootstrap -config "$HOME/config.json" -device-file "$HOME/device-match.json" -speak
```

若需要短信/邮箱验证码，程序在 `bootstrap-status.json` 写入 `verification_required` 并等待约十分钟。另一个 Mac 终端中，把验证码通过编辑器填入 `.secrets/otp.txt`，仅含验证码，再执行：

```sh
chmod 600 .secrets/otp.txt
adb -P 5038 push .secrets/otp.txt /data/adb/lx04-deepseek/otp.txt
adb -P 5038 shell chmod 600 /data/adb/lx04-deepseek/otp.txt
rm .secrets/otp.txt
```

程序读取后删除音箱上的输入文件；不要把验证码直接写进公开终端录屏。登录成功时保存 `.mi.token`，将匹配出的 Miot DID 写回私密配置，并在 `-speak` 下发送一句测试播报。没有唯一精确匹配就停止，不回退到另一台同型号设备。验证码流程失败时先看脱敏状态，不要不断重发短信；风控/验证码类型可能需要后续适配。

默认不要开启认证诊断环境变量。必须排障时，文件的敏感范围及清理要求见 [SECURITY.md](../SECURITY.md)。

## 5. 先前台验证，再配置开机启动

在已经设置环境变量的设备 shell 执行：

```sh
./lx04-agent -config "$HOME/config.json"
```

看到 `ready` 后说“小爱同学，彩虹是怎么形成的”，再测试天气、穿衣及自己常用的一条家居指令。确认后 Control+C，等待恢复声音并退出。不要同时运行两个 agent。

可选检查工具：`./lx04-netcheck -config "$HOME/config.json"` 只查询模型列表，增加 `-chat` 会发起短对话；`./lx04-searchcheck -config "$HOME/config.json"` 会调用付费搜索和模型。它们仍需要上面的 HOME/CA/DNS 环境。

确认 Magisk `service.d` 已实际工作后，在 Mac 执行：

```sh
adb -P 5038 shell 'mkdir -p /data/adb/service.d'
adb -P 5038 push scripts/device-service.sh /data/adb/service.d/lx04-deepseek.sh
adb -P 5038 shell 'chmod 700 /data/adb/service.d/lx04-deepseek.sh'
adb -P 5038 reboot
```

重新连接后检查新进程、新日志与语音表现。旧 PID 文件存在不等于自启成功。若 Magisk 日志显示 `environment incomplete`，参考[技术报告第 9 节](改造过程与修改技术报告.md)：原机补齐的是同版官方运行组件，不是下载其他型号镜像。

公开启动模板先等开机和网络，再读取 `dns-server.txt`；未提供时尝试 Android DNS 属性和默认网关。默认网关不一定提供 DNS，推荐明确配置。只修改本进程 resolver，不改原厂系统网络设置。

## 6. 验收与维护

至少核对：无前缀知识问答、原生天气、结合当地天气的穿衣建议、常用米家指令、联网问题、请求失败后的声音恢复、重新上电自启。原机历史结果见[验证摘要](验证与构建摘要.json)，自己的设备应记录自己的结果。

日常停用、音频恢复、配置位置及费用说明见[使用与维护](使用与维护.md)。停用附加程序不等于恢复启动锁，也不会自动撤销持久 USB 设置。
